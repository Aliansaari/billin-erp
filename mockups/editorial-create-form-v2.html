Why this layout — v2 Workspace

Section nav as muscle memory

F2 / F3 / F4 jump between Identifiers / Pricing / Inventory without arrow nav. The rail visually anchors which step you're on; the right pane shows only that step's fields, so the operator never scrolls through 25 fields at once.

Step counter + done state

Top-right of the pane shows Step 1 of 3. Already-edited sections get a green ✓ in the rail. Operator always knows where they are and where they've been. F1 still saves the WHOLE form (no per-step save).

Short forms collapse

Category has only one section, so it falls back to a single-pane compact modal (~460 px wide) — no empty rail. Same shell logic, same F-key footer; the rail just doesn't render when there's nothing to navigate.

Trade-off vs v1

v1 keeps everything visible — fast for 3-field forms, scrolly for Product. v2 is the opposite — slower for tiny forms (extra rail chrome), much faster for Product because each step is one screen. Choose v2 if your most-edited form is the complex one.

Keyboard contract — same as v1

Esc cancel · F5 reset · F8 save & close · F1 save · plus F2/F3/F4 for section jumps and ↑↓ when focus is on the rail.

Width

Modal is ~820 px (rail 200 + pane 620). Comfortable on a 1366-wide laptop with the sidebar collapsed; on smaller windows the rail can compress to icons-only or hide behind a hamburger toggle (deferred — first ship at 820).
