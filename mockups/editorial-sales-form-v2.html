Editorial v2 · Sales Bill Form

Long bills should feel like writing in a book.

Five new entry-row variants below, picking up where v1 left off. Each is judged against one bar: does an operator entering 30+ line items finish the day energised, or worn down? The principles — calm surface, monospace numerics, persistent labels, JS-free focus state — come from the editorial palette already used by Sales Report and Day Book, so any pick drops straight into the running app's design language. Below the variants, my pick of three. Below that, a complete Sales Bill Form built around variant 4 (Editorial Ledger Row) — with the totals, information panels, and action bar redesigned alongside.

Why this for long sessions

  • Two hairlines, no rectangles. The row is bounded by a 1.5px ink rule on top and a 1px cream rule on bottom — a single horizontal shape, not 11 stacked boxes. The eye reads it as one line of a ledger book.
  • Active state warms instead of shouting. Active cell tones up to --bg-cell (warm cream) with a 2px accent underline — no saturated ring, no shadow. Across 30 line items the visual cost of a focus change is near-zero.
  • Numeric baseline rule. Numeric cells get a thin dotted bottom rule under the digits — accountant's habit. Drifts (1,996.00 vs 19,960.00) line up vertically.
  • Labels recede correctly. 9px / 1.2px tracking / --ink-3 — present at all times, never compete with the value.
  • +ADD is INK, not accent. The terminator cell uses the page's darkest ink, not the saturated accent. After commit you don't get hit with a colour change every line. The accent stays reserved for "active cell" — the only thing the eye should chase.
  • Cost. 46px row height (8px taller than today) in exchange for permanent column legibility + rest. Net positive at 5+ items, decisive at 30+.

Why this for keyboard-first power users

  • Tab-stop is visible. Each cell carries an ordinal pill (1–11) — experienced accounting-software users mentally count cells; here we count for them.
  • Progress bar = finish line. The 3px bar on top fills as the caret advances. By the 30th line the operator has built muscle memory of the bar's slide; entering Qty (cell 7) feels close to "done", not stranded somewhere in the middle.
  • Commit hint where it belongs. The "↵ next" badge sits on the active cell only — no permanent visual weight, but the moment you're at cell 7 (Qty) it whispers Enter to commit + jump to next item. Reduces the "what do I press now" hesitation that breaks rhythm.
  • +ADD uses the accent (not ink). Different from Variant 4 — here +ADD is also the keyboard "submit", so it earns the accent colour. The progress bar above it ties them visually.
  • Trade-off vs Variant 4. Slightly busier (the ordinal pills carry visual weight). Worth it for an experienced-operator; possibly noisy for a first-time user.

Why this for the most minimal aesthetic

  • One hairline below. That's it. The row dissolves into the page — most calm option of all five.
  • Caret line is the only chrome. Hover lights a faint underline (rule-strong); active brightens it to accent and thickens to 2px. The caret's position is unmistakable, the field itself is invisible.
  • Subtle column separators. A single · centred between cells, in --ink-5. It's there for orientation, not for decoration.
  • +ADD is a pill, off the strip. Because there's no row container to sit inside, the +ADD button stays as a discrete pill — the only visually dense object on the row.
  • Trade-off. Reads beautifully in a wide page. At narrow viewports the absence of borders makes adjacent labels visually merge — Variant 4's hairlines win there.

What changed in the form (vs today's production page)

  • Top strip is now a 3-band grid (doc · mode · meta) instead of a single flex row. The mode toggle (Items / Amount) becomes a centred segmented pill — the only tap target the operator needs to flip; everything else either reads or is editable in place.
  • Customer strip has the info inline. The dropdown stays at 320px, the entire info row (City · Phone · Balance · Credit pill) flows beside it on the same row. Replaces today's stacked "info strip" beneath the dropdown.
  • Three footer cards collapse into two panes:
    • Compose — sale type + salesman + notes — a calm composition surface with item/qty/box stats as small chips in the panel header.
    • Math + Pay — bill-math breakdown (sub-total, discount %, GST split, freight, round-off) on the left; payment mode + cash received + return + paid-in-full pill on the right; a 1px vertical rule between. The grand total renders in display-serif at 26px — a hero number.
  • Items table is striped + sticky-header. Every other row picks up --bg-cell so a 30-line bill stays scannable. The header row sticks to the top of the scroll container so the operator sees Qty / Rate / GST% labels even at row 28.
  • Action bar is keyboard-first. Each action carries its kbd hint inline, the destructive (Reset) is muted-warn, the credit-only path is muted-warn-soft, and the primary Save & Receive is the only saturated button on the page (indigo). Visual hierarchy = behavioural hierarchy.
  • Sidebar is icon-only at 72px. The form earns the page width; chrome doesn't.
§4 · WIRING

How to land this in code

touchpoints · CSS shape · React-state cost

Files

  • src/pages/sales/SalesBillForm.jsx — entry row (replace the sbf-top-row-2 block with the cell grid; each <Form.Item noStyle><Input/></Form.Item> becomes a <div className="cell"><div className="cell-lbl"></div>{existing AntD control}</div>) + a small footer rewrite (the 3 cards become 2 panes — Compose + MathPay).
  • src/pages/sales/sales-bill-form.css — add the .entry-ledger styles + the .compose / .mathpay footer styles. The existing .sbf-page .ant-input / .ant-select-selector overrides stay; we add a scoped borderless override under .entry-ledger .cell .ant-input so AntD's own border drops out inside cells.
  • src/pages/purchase/PurchaseBillForm.jsx + purchase-bill-form.css — mirror the same change so the two flows stay symmetric.

CSS strategy

  • Active state via :focus-within. No React state; the cell that contains the focused input becomes the active cell. Caret moves → active state moves. Zero re-renders.
  • AntD borderless inside cells. .entry-ledger .cell .ant-input, .entry-ledger .cell .ant-select-selector { border: 0 !important; background: transparent !important; box-shadow: none !important; padding: 0 !important; }
  • Numeric mono right-align. .entry-ledger .cell.numeric .ant-input { font-family: var(--font-mono); text-align: right; } Same on the items table cells (already half-applied — .report-editorial .ant-table-tbody uses tabular-nums; we extend to the bill form's table).
  • Sticky table header. position: sticky; top: 0; on thead th with the table inside an overflow-y: auto wrapper. Already the pattern in the new Day Book / Sales Report — keeps the codebase consistent.

What we DON'T change

  • The Form.Item bindings — value flow stays exactly as today; only chrome moves.
  • Keyboard semantics. Tab walks left-to-right, Enter on Qty fires +ADD, F1 saves & receives.
  • The barcode-scan flow (auto-fills Product/Rate/Size).
  • The hold/draft flow.
  • Permissions, validation rules, the customer-required logic added in the cash-sales feature.

Estimated diff

Roughly 180 lines added (SalesBillForm + PurchaseBillForm) and 200 lines of CSS, mostly mechanical — markup re-shaping, no behaviour change. Single commit feasible. Verifiable by opening any in-progress bill: the layout updates, the values stay where they were.
