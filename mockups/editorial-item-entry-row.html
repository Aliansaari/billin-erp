Why this one

  • One shape, one outline. The whole entry row reads as a single object — like a row in the line-items table beneath it. The eye doesn't have to re-anchor at every box edge.
  • Labels stay visible. Tiny uppercase label sits inside each cell (top edge), so the operator never has to remember which cell is Disc% vs GST% mid-keystroke. Today's placeholders disappear the moment you type a character.
  • Active cell is unmistakable. White fill + 2px accent inset ring on the focused cell; everything else stays in the cream cell-tone. Keyboard tabbing telegraphs itself.
  • Same vertical real estate as today. Cell height ~46px (label 13px + input 28px + padding). The current row is 38px without labels; adding the label is a 8px trade for permanent column legibility.
  • +ADD is part of the strip. Right-most cell, accent fill, same height. Visually it's the row's terminator — the "I'm done with this line" affordance — instead of a button hanging off the end.
  • Numeric cells right-align with mono digits. Rate / Qty / Disc% / GST% all use Geist Mono with right alignment, so amounts column-align across both the entry row and the table beneath.
  • Hover discoverability. Hovering any cell warms its bg (cell→panel) so a mouse user sees the cell as clickable without a border change.
  • Keyboard ergonomics unchanged. Tab still walks left-to-right; Enter on Qty still fires +ADD. Cell :focus-within drives the active-state ring so no JS is required.

SPEC Implementation notes — shared between all three variants; only the container CSS swaps.

To wire any variant

  • Files: src/pages/sales/SalesBillForm.jsx (the JSX block currently labelled "Entry row — only in itemised mode" near className="sbf-top-row-2") and the matching block in src/pages/purchase/PurchaseBillForm.jsx (className="pbf-top-row-2").
  • Markup change. Replace each <Form.Item noStyle><Input ... /></Form.Item> with a <div className="cell"> wrapping a tiny <div className="lbl"> and the existing AntD control. The control uses the borderless val class (transparent bg, no border, full-width). Form.Item still owns the value binding — only the visual chrome changes.
  • Active state. CSS-only via :focus-within on .cell — no React state, no extra render. The active-cell ring follows the caret automatically as Tab walks the row.
  • AntD overrides. Add to sales-bill-form.css a scoped block: .entry-grid .ant-input, .entry-grid .ant-select-selector { border: 0 !important; background: transparent !important; box-shadow: none !important; padding: 0 !important; } so AntD's own border/bg doesn't fight the cell.
  • Keyboard semantics unchanged. Tab walks left-to-right; Enter on Qty still fires +ADD; Shift+Tab walks back. The barcode auto-fill flow that fills Product/Rate/Size/etc on a successful scan keeps working — those Form.Item bindings don't move.
  • Sizes. Cell height 46px (label 13 + input 28 + padding 5). Total row height 46px — 8px taller than today's 38px row, in exchange for permanently visible column labels.
  • Mobile / narrow viewport. The grid template stays the same on desktop; at max-width: 1100px you can wrap the grid into 2 rows (grid-template-columns: repeat(6, 1fr) first row, repeat(5, 1fr) second) via the existing @media block in sales-bill-form.css.
  • Themes. All colors flow through the existing CSS vars (--bg-panel, --rule, --accent) so the strip re-skins under the user's classic / modern / dark theme switch without further work.
