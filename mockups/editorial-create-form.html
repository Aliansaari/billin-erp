Create form mockup — proposed `EntityFormModal`

Static mockup. No JS, no real data. Goal: one shared shell (title strip, section frame, footer with F-key bindings, dirty-state confirm) used by every entity create/edit form. F-keys match the existing bill forms — F1 Save · F5 Reset · F8 Save & Close · Esc Cancel. Three variants below show the same shell housing different field bodies: Product (complex, sectioned) · Customer (medium) · Category (minimal).

Design notes — what's intentional

Solid, not soft

Modal corners are 6px. Field corners are 4px. Borders are 1px hairlines at --border:#2a313e — a deliberate step darker than the previous "muted-grey" treatment. No drop shadow on cards inside the modal; only the modal itself lifts off the page.

Typography hierarchy

Title 15/700, section eyebrow 9.5/700/uppercase/1.4em letter-spacing, field label 11/600/uppercase/0.04em, value 13/500. Three weights (500 / 600 / 700) plus uppercasing carry the hierarchy — no extra colour noise needed.

F-key footer matches the bill forms

Pinned to the bottom: Esc Cancel · F5 Reset · spacer · F8 Save & Close · F1 Save. Each is labelled with a real <kbd> chip so the muscle-memory user sees the binding without hovering. F1 is the primary action, accent-filled, right-most.

Section anchors

Long forms (Product) get Alt+1 / Alt+2 / Alt+3 jumps rendered as a small pill on the right of each section header. Short forms (Category) skip them entirely — the shell hides the chip when only one section exists.

Field affordances

Numerics use font-variant-numeric: tabular-nums so columns align. Suffix units (₹ · %) live in their own muted slot to the right of the input — clearer than placing them as a placeholder. Required fields carry a single red asterisk (no label colour change — just one signal, one place).

Relation pickers

Category, Party, Godown — anything that links to another entity — gets ⌘K picker + + new shortcut. The "+ new" path opens the SAME modal shell for the related entity, stacked at z-index+1; closing it returns the operator to the original form with the new value pre-selected.

Dirty-state confirm

Esc with no edits → close instantly. Esc with edits → small inline confirm (no second modal): "Discard changes? Esc again, or F1 to save." Two-keystroke escape preserves the no-modal-stack rule.

Phase 4: global "Create…" launcher

Optional follow-up. Cmd+N (or Ctrl+N) opens a small palette with a single search input — type prod, cust, cat → Enter opens the matching create modal. Built on top of the same shell; zero duplicate modal code.
How it lands in the app: The modal sits in the centre of the viewport with a rgba(0,0,0,.55) dim backdrop covering the page behind it. Only one modal open at a time except in the relation-picker → "+ new" stack case noted above. The page underneath keeps focus inert so Tab stays inside the modal until close.
